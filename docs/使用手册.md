# 局域网互动聊天室 · 使用手册

> 返回 [项目首页](../README.md) ｜ 本文档面向**实际使用者（教师）**，讲清每个按钮、每份文件、每条规则。

面向教师机部署、学生机浏览器访问的轻量聊天室。包含：

- 五个公共房间：综合大厅、游戏讨论、音乐电台、灌水乐园、学习交流
- 注册账号、游客进入、管理员账号
- WebSocket 实时文字聊天
- 在线用户列表和人数统计
- 表情按钮、简单虚拟礼物
- 多房间自由切换，各自独立的消息记录和在线人数
- 私聊：点击在线用户后选择“私聊”
- 头像、等级、金币和等级商城
- 管理员禁言、解除禁言、踢出用户、删除消息；禁言时长 2 分钟，被踢后 3 分钟内不能重新进入
- **房主**：管理员可以把某个学生设成「某个房间」的房主，房主能改本房间公告、在本房间禁言/解除禁言。
  房主不是第四种身份 —— 他在 A 房间是房主，换到 B 房间就是普通用户，一个房间也可以有多个房主（上限 5 个）
- 房间互动中心：抽奖、转盘、大喇叭、红包、竞猜、猜数字、猜歌名、成语接龙、真心话和大冒险
- **互动消息不刷屏**：抢红包、竞猜投票、接龙、抽奖这类「一人刷一条」的流水会自动收成一条
  「活动消息 N 条」的折叠带，真人说的话始终留在聊天区；开局、开奖、答对、大喇叭这些低频的照常单独显示
- 聊天内容违规词自动屏蔽，发言者扣除 5 金币并收到系统提示；同一会话内连续 3 次违规自动禁言 1 分钟，游客没有金币可扣，同样按次数禁言
- 违禁词库放在根目录的 `违禁词库.txt`，用记事本改完存盘即生效，不用重启服务
- 房间公告**每个房间一份**，放在根目录的 `公告\` 文件夹里（`公告\lobby.txt`、`公告\games.txt`……），
  用记事本改完存盘即生效，不用重启服务、也不用重新构建前端；房主也可以在页面上改自己房间那一份
- 昵称与聊天内容使用同一套审核规则，含违规词的昵称无法注册或进入
- 聊天表情、互斥的文字颜色/彩虹/闪亮效果；房间金币榜、财富榜、魅力榜和活跃榜
- SQLite 保存注册用户和聊天记录
- 左下角个人虚拟宠物：注册账号达到 5 级后首次可免费领养小鸡 / 小猫 / 小狗；以后更换宠物扣除 20 金币并保留原状态，游客不能养
  - 宠物状态按时间下降：饥饿每分钟 1.2、口渴每分钟 1.5、清洁度每分钟 0.8；喂食、喂水、清洁用品在等级商城购买，点击宠物会触发爱心反馈。
- 2010 年代风格的蓝色渐变、边框面板和工具栏界面

技术栈：FastAPI + Uvicorn + WebSocket + SQLite；前端源码使用 Vue 3 + Vite，构建结果已经放在 `static/dist`，运行时不需要 Node.js。

## 启动

教师机安装 Python 3.11 或更高版本，双击根目录的 **`聊天室控制台.bat`**。第一次运行会自动创建虚拟环境并安装依赖，之后会弹出一个控制台窗口，启动、停止、重启、备份、重置都在这个窗口里点按钮完成。

控制台窗口里的按钮：

控制台上的按钮分两行，上面一行管服务，下面一行管账号和数据，每行开头都有标签标明这一行是干什么的：

**服务控制**

| 按钮 | 作用 |
|---|---|
| 启动服务 | 后台启动聊天室（不会留黑窗口），就绪后状态灯变绿 |
| 停止服务 | 只关闭正在监听 9000 端口的那个 Python 进程，不动同机的其他程序 |
| 重启服务 | 停掉再起来，改了后端代码后用这个 |
| 打开聊天室 | 用默认浏览器打开本机地址 |

**账号数据**

| 按钮 | 作用 |
|---|---|
| 成员列表 | 列出全部注册账号（含管理员），选中一个看他的全部信息（**不含密码**）；学生忘记密码也在同一个窗口里重置 |
| 清空聊天记录 | **不可恢复**：先自动备份到项目外面，再清空聊天记录；账号、金币、等级、道具全部保留 |
| 备份与恢复 | 备份：把数据库 + 头像图片存到 `backups\chatroom_时间\`，服务运行中也能做。恢复：同一个窗口里选中任意一份备份，点「还原」就退回去 |
| 重置数据 | **不可恢复**：先自动备份到项目外面，再删除全部账号和聊天记录 |

关窗口时会问你要不要连服务一起关掉：选「否」就只关窗口，聊天室继续跑着，学生照常使用。

### 成员列表：一次看到全部注册账号

点控制台上的 **「成员列表」**。这是本机窗口，**只在这台教师机上能看**，学生那边没有任何入口。

- **名单**：全部注册过的账号（**包括管理员**，管理员排在最前），每行显示昵称、账号、角色、等级、金币、发言条数、注册时间。
  **点表头可以排序**（再点一次反过来）；上面的搜索框昵称、账号、真实姓名、班级、个性签名都能搜；右边还有「只看管理员 / 只看普通用户」。
  名单是打开时读一次，学生刚注册完点一下 **「刷新」** 就能看到。
- **详情**：左边点一个人，右边显示他的全部信息 —— 昵称、账号、角色、等级、经验、金币、魅力、真实姓名、班级、个性签名、注册时间、最后发言、发言条数、全站禁言、禁入冷却、本房间禁言、房主房间、宠物状态、物品栏、账号编号。**没有密码**：密码在库里是单向哈希，这里也压根不读那一列。
- **导出 CSV**：点 **「导出 CSV」**，导出的是**当前筛选之后看到的结果**（先搜「八年级3班」再导出，就只有八年级3班）。文件用 Excel 双击直接打开，中文不乱码。⚠️ 里面有真实姓名和班级，注意存放位置。
- **游客不在名单里**：游客没有账号记录，所以不会出现。

### 学生忘记密码怎么办

在 **「成员列表」** 窗口里选中那个学生 → 点 **「重置选中成员的密码」**（或者直接**双击那一行**）→ 确认，他的密码就变回 `123456`。

- **只改选中的这一个账号**，别人的密码、管理员密码都不受影响。
- 学生的等级、经验、金币、道具、聊天记录**全部保留**，只有登录密码变了。
- **不用停服务**：重置完他立刻就能用新密码登录，正在上课也随时能改。
- 已经重置过的账号前面会打一个绿色的 ✓，方便你确认改没改成功。
- **管理员账号不能在这里重置**（按钮是灰的）。
- 想换默认密码，改 `manage.py` 里的 `RESET_PASSWORD` 一行就行。

不改代码的话，也可以走命令行：`manage.py passwd 账号`（详见下方「命令行方式」）。

### 怎么只清空聊天记录（保留学生账号）

点控制台上的 **「清空聊天记录」**：

- **只清聊天记录**（含私聊、礼品和活动播报）；**注册账号、金币、等级、道具、房间活跃榜全部保留**，学生不用重新注册。
- 房间、商城物品、**进行中的红包/竞猜**都不受影响。
- 删之前会自动备份到项目外面（`局域网聊天室_清空记录备份_时间\`），**备份失败就不删任何东西**。
- **不用停服务**：正在上课也能清；清完后让学生按一次 **F5** 刷新，浏览器里的旧消息就看不到了。
- 图省事也可以走命令行：`manage.py clear-messages`（会要求输入 Y 确认）。

> 如果连账号也要一起清掉（相当于恢复出厂设置），那要用 **「重置数据」** ——
> 它会连注册账号、金币、道具一起删，学生需要重新注册。

### 备份了怎么还原

点控制台上的 **「备份与恢复」**，窗口里两件事都能做。

**上半部分「立即备份」** —— 点一下就把当前状态存一份到 `backups\chatroom_时间\`，里面有：

- `chatroom.db`：聊天数据库（账号、金币、等级、道具、聊天记录）
- `avatars\`：头像图片
- `还原说明.txt`：这份备份是什么、怎么还原

**下半部分列出所有能还原的备份**（最新的排最上面）。点一下选中，再点 **「还原选中的备份」** 就退回去了。控制台会自动：

1. 先停下服务；
2. **把你现在的数据另存一份到项目外面** —— 万一选错了备份，还能拿这一份退回来；
3. 用选中的那份备份覆盖现在的数据；
4. 完成后回到主窗口点「启动服务」就能用。

> **还原是按时间点整体回退**：备份之后新产生的聊天记录和账号都会消失。
> 所以系统每次还原前都会先替你另存一份当前状态，不会出现「退不回去」的情况。

列表里除了手工备份，还会出现这些**自动备份**（都放在项目外面，各留最近 5 份）：

| 目录前缀 | 什么时候生成的 |
|---|---|
| `局域网聊天室_重置备份_时间\` | 点「重置数据」之前 |
| `局域网聊天室_清空记录备份_时间\` | 点「清空聊天记录」之前 |
| `局域网聊天室_还原前备份_时间\` | 每次还原之前 |

命令行等价物：`manage.py backup` 备份，`manage.py restore` 列出并选择要还原的一份。

如果修改了 `frontend` 下的前端源码，需要在开发机执行 `npm install` 后运行 `npm run build`，再启动服务。

### 虚拟宠物素材

当前内置的是可替换的像素风 SVG 占位素材，位于 `static/pets/`：

- `scene.svg`（蓝天、云朵、草地、小树和背景小房子）
- `house.svg`
- `chicken.svg`
- `cat.svg`
- `dog.svg`

以后如果准备新的宠物图片，可以继续放在这个文件夹，并按现有文件名替换；如果使用新的宠物种类，再在前端的 `PET_CHOICES` 和后端 `PET_TYPES` 中登记。建议素材采用透明背景、正方形画布，并保留像素边缘。

启动后，教师机查看局域网 IP（Windows 可在命令提示符运行 `ipconfig`），学生机 Edge 访问：

```text
http://教师机IP:9000
```

管理员不需要单独入口，在首页的“登录账号”标签中登录即可；登录后右侧在线用户菜单和消息旁会显示管理员操作。可以在启动前设置环境变量 `CHAT_ADMIN_USER`、`CHAT_ADMIN_PASSWORD` 修改管理员账号和密码。

## Windows 防火墙

如果学生机无法访问，首次启动时允许 Python 通过“专用网络”防火墙；也可以在 Windows 防火墙入站规则中放行 TCP 9000 端口。

## 数据位置

注册用户和聊天记录保存在 `data/chatroom.db`。删除这个文件会清空本地数据，重新启动时会创建默认管理员账号。

- `违禁词库.txt`：聊天违禁词词库，用记事本直接维护，改完存盘即生效（详见下一节）。
- `公告\`：**每个房间一份**公告 txt（文件名是**房间号**：`公告\lobby.txt`、`公告\games.txt`……），
  用记事本直接维护，改完存盘即生效（详见下一节）。
- `公告.txt`：老版本留下的全局公告。**首次启动新版本时会被自动复制成 `公告\lobby.txt`**，原文件保留不动，你可以自己决定删不删。
- `logs/server.log`：服务的运行日志。启动失败时原因就写在这里，控制台窗口的「运行记录」也会实时显示；点「打开日志文件」可以看完整内容。
- `backups\chatroom_时间\`：「备份与恢复」窗口里点「立即备份」生成的一份备份（数据库 + 头像图片 + 还原说明）。
  还原不用手工拷文件 —— 在同一个窗口里选中它，点「还原选中的备份」即可。
  老版本留下的 `backups\chatroom_时间.db` 单文件备份也会出现在列表里、也能还原，只是里面没有头像图片。
- 项目外面（与项目同级的目录）的 `局域网聊天室_重置备份_时间\`：「重置数据」按钮在删除前自动生成的备份，只保留最近 5 份。里面附有「还原说明.txt」，写明怎么恢复。
- 项目外面的 `局域网聊天室_清空记录备份_时间\`：「清空聊天记录」按钮在删除前自动生成的备份，同样只保留最近 5 份，也附有「还原说明.txt」。
  两种备份各留各的，清空聊天记录不会把重置备份挤掉。
- 项目外面的 `局域网聊天室_还原前备份_时间\`：每次「还原备份」之前自动生成的备份，同样只保留最近 5 份。
  它的意义是「后悔药」—— 还原选错了备份，用这一份就能退回还原之前的状态。

## 房间公告怎么维护

左侧面板的「本房间公告」和右上角「📢 房间公告」弹窗显示的是**同一份内容**，每个房间各自一份，
放在项目根目录的 **`公告\`** 文件夹里：

| 房间 | 公告文件 |
|---|---|
| 综合大厅 | `公告\lobby.txt` |
| 游戏讨论 | `公告\games.txt` |
| 音乐电台 | `公告\music.txt` |
| 灌水乐园 | `公告\water.txt` |
| 学习交流 | `公告\study.txt` |

> 文件名用的是**房间号**（纯字母），不是房间里显示的中文名 —— 中文文件名在另存为、命令行和打包脚本里
> 反复出问题，而且房间名以后可能会改，房间号不会。

- **改完保存就生效**，不用重启服务、不用关控制台、也不用重新构建前端。
  同房间已在线的人会**立刻收到推送**（不用刷 F5）；页面重进 / 断线重连时也会重新下发一次。
- **改完聊天区会插一条系统提示**（`📢 房主 小甲 更新了本房间公告`），
  免得有人正在打字、压根没注意左侧面板悄悄换了字。提示**只发给本房间**。
- 这条提示**不进聊天记录**，刷新页面就没了 —— 它是一条「变更通知」，不是一条消息；
  公告正文本来就持久化在文件里，左侧面板一直显示着。
- 正文一个字都没改就点保存，不会再发提示（免得反复点保存把聊天区刷满）。
- **房主也可以在页面上改自己房间那一份**：右上角「📢 房间公告」→「✏️ 编辑本房间公告」。
  改的是同一个文件，所以「一处内容、两个入口」，不会两边打架。
  管理员改任意房间的公告时，提示里的落款是「管理员」而不是「房主」。
- 一行一行写，`#` 开头的整行是说明，不会显示给学生看。
- 换行会保留，可以分行写；上限 200 字，超了服务端会直接拒绝并说明原因。
- **直接改文件不过滤违禁词**（内容由老师自己维护），保存前请自己检查一遍；
  **房主在页面上保存的内容会过一遍违禁词过滤**（房主也是学生）。
- 文件误删也不要紧，进入那个房间时会自动重新生成一份默认公告。

## 房主怎么用

「房主」**不是第四种身份**，而是「**某个人 × 某个房间**」的一条授权：

- 管理员在在线名单里**右键**某位同学 → 「🏠 设为本房间房主」；再点一次是「撤下本房间房主」。
- 房主能做两件事，**都只在本房间生效**：
  1. 改本房间的公告（见上一节）；
  2. 在本房间禁言 / 解除禁言普通用户和游客。
- 房主**不能**：任命别的房主、全站禁言、踢人、删消息 —— 这些都是管理员专属。
- 他在 A 房间是房主，换到 B 房间就是普通用户；一个房间最多 5 个房主。
- 授权是**落库**的，重启服务后依然有效。房主身份会显示在在线名单里（昵称旁边的金色「房主」小徽章）。
- 房主在被禁言期间不能执行管理操作。

**禁言分两种**，别混：

| 动作 | 谁能用 | 生效范围 | 落库位置 |
|---|---|---|---|
| 本房间禁言 2 分钟 | 管理员 / 本房间房主 | 只在被禁言者**当前所在的那个房间** | `room_mutes` 表 |
| 全站禁言 30 分钟 | 只有管理员 | **所有房间**都发不了言 | `users.muted_until` 字段 |

所以要「让某个学生在某个房间闭嘴」用第一种；「让他哪儿都说不了话」用第二种。

## 玩小游戏会不会把聊天刷没

不会。互动中心产生的消息**按档位分两类**，判据是「旁观者会不会真的关心」，不是「它属于哪个功能」：

| 档位 | 哪些 | 在聊天区长什么样 |
|---|---|---|
| **通知**（单独显示） | 开局、开奖、红包发出、猜中答案、大喇叭、**真心话 / 大冒险抽题**、**别人的回答** | 照常占一行，和普通消息一样 |
| **流水**（折叠） | 抢红包、竞猜投票、每句接龙、每次抽奖 / 转盘 | 收成一条`活动消息 N 条 · 红包 3 接龙 4`，点一下展开看明细，再点收起 |

**为什么这么分**：一轮拼手气红包 50 份、一轮接龙十几句、一次竞猜三十票，全是「每人一条」——
真人聊天会被顶到屏幕外面去。而这些内容在互动中心的面板里本来就看得到（谁领了多少、各选项多少票、
当前要接的词），所以折叠**不会丢任何信息**。

★ **真心话 / 大冒险为什么留在「通知」档**：它们是**等人回应**的事件，不是流水。
折进折叠带就等于「没人知道有题在等」，题直接作废了——省下的那点版面，换不来「有人回应」这个前提。
同理，别人提交的回答也单独显示：那才是这个玩法真正的内容。

折叠带只在**连续**的流水消息之间合并：中间只要有人说了一句话，就断开成新的一条带子，
这样对话的上下文永远完整。带子里的明细每条都能单独删（管理员）。

> 想加新玩法时，在 `app.py` 的 `ACTIVITY_STREAM_KINDS` 里登记它的类型名就能决定它折还是不折。
> **忘了登记也不会出事** —— 没登记的一律按「通知」处理，最坏结果是多占几行，绝不会把消息藏起来。

## 真心话 / 大冒险怎么玩

互动中心 →「房间小游戏」→ **抽真心话 / 抽大冒险**。抽出来的题会**公开给全房间**，
任何人都能回答，**回答实名公开**。

| 谁 | 做什么 |
|---|---|
| 抽题的人 | 点一下抽出一道题，题目立刻出现在全房间（也可以自己不答） |
| 其他同学 | 在互动中心里看到题目 → 输入框写回答 → 提交 |
| 所有人 | 提交后**立刻**在答题板上看到大家的回答（不用刷新） |

回答一道给 **1 金币 + 1 房间金币**。规则只有三条：

- **每个房间同时只有一道题**。上一题结束（2 分钟）后才能抽下一题。
- **每人每题只能答一次**。答完输入框会消失 —— 想再来一题，等下一轮。
- 题目结束前都可以答；超时后答题板会列出最近抽过的题和已回答的人数。

> **为什么给的金币这么少**：答题几乎零成本（不用抽、不用下注），奖励又是白拿的。
> 定成 0 就没人答了，定成 10 就成了刷币口子。1 金币刚好让人愿意开口，又不值得专门去刷。
> 那两条闸门（同时一题、每人一次）就是为这个 1 金币配的，**别去掉它们**。

**回答会过违禁词过滤**：内容含违规词会被打成星号照发（和普通聊天一样）。
这一点和大喇叭不同 —— 大喇叭是**付费**内容，含违规词直接退回且不扣钱。

## 违禁词库怎么维护

违禁词都写在项目根目录的 **`违禁词库.txt`**，双击就能用记事本打开：

- **改完保存就生效**，不用重启服务，也不用关控制台窗口；新加的词对**历史消息**同样有效（刷新页面即可看到旧消息也被打上星号）。
- 一行一个词条，`#` 开头的整行是说明，不会当成词条。
- 词条按**辱骂 / 色情 / 暴力 / 赌博 / 英文脏话**分了类，默认生效约 130 条，照着分类往下加一行即可。
- 文件后半段是「默认关闭」的词（容易误伤的、广告诈骗的、赌毒的）。确认需要时，**删掉行首那一个 `#`** 就启用了。
- 插空格、插标点、全角字母都不用担心，不必为每种写法各写一行：`傻 逼`、`傻。逼`、`傻-逼`、`傻Ｂ`、`f u c k` 都会被一起拦下。
- 文件误删也不要紧，下次过滤时会自动重新生成一份默认词库。

新加的词如果怕误伤正常用语，可以在词条后面加标记（平时用不上）：

| 写法 | 意思 | 例子 |
|---|---|---|
| `词条 <-字` | 前面紧挨着这个字就不算 | `妈的 <-我`，让「我妈的病」不被拦 |
| `词条 ->字` | 后面紧挨着这个字就不算 | `他妈 ->妈`，让「他妈妈」不被拦 |
| `词条 =` | 英文、数字词必须独立成词 | `fk =`，让「fk」被拦而「fkzz」不受影响 |

下面这些误伤保护已经内置，**不用你设置**，词条删了再加回来也依然有效：
「他妈妈是老师」「我妈的病好多了」「今天我生日你没来」「USB 接口」「我操作一下」。

词库支持三种编码：UTF-8（带不带 BOM 都行）、记事本「另存为 ANSI」的 GBK。

## 命令行方式（可选）

不想开窗口的话，这些命令等价于上面的按钮（先确保已装好依赖）：

```bat
.venv\Scripts\python.exe manage.py start     :: 后台启动服务
.venv\Scripts\python.exe manage.py status    :: 看服务在不在跑
.venv\Scripts\python.exe manage.py stop      :: 停止服务
.venv\Scripts\python.exe manage.py backup    :: 备份（数据库 + 头像图片）
.venv\Scripts\python.exe manage.py restore   :: 列出全部备份，输入编号把它还原回来
.venv\Scripts\python.exe manage.py reset     :: 重置（会要求输入 Y 确认）
.venv\Scripts\python.exe manage.py clear-messages  :: 只清空聊天记录，账号保留（会要求输入 Y 确认）
.venv\Scripts\python.exe manage.py passwd                :: 列出全部学生账号
.venv\Scripts\python.exe manage.py passwd 账号            :: 把这个学生的密码重置为 123456
.venv\Scripts\python.exe manage.py passwd 账号 新密码      :: 重置成指定密码
```

以前的 `start.bat` / `stop.bat` / `backup.bat` / `reset.bat` 已经合并进控制台窗口，原件放在 `backups/old_bat_20261001/` 里备查，平时用不到，可以删掉。

## 自检（可选）

改动过代码之后想确认没改坏，双击根目录的 **`全量检查.bat`**，或者在命令行跑：

```bat
.venv\Scripts\python.exe tests\full_check.py             :: 跑全部四层，约 80 秒
.venv\Scripts\python.exe tests\full_check.py --only L1   :: 只跑静态检查，1 秒内
.venv\Scripts\python.exe tests\full_check.py --only L1,L3
.venv\Scripts\python.exe tests\full_check.py --no-gui    :: 没有桌面环境时跳过控制台那一层
.venv\Scripts\python.exe tests\full_check.py --keep-temp :: 保留临时目录，失败后好翻现场
```

四层各管什么：

| 层 | 检查内容 | 本机实测 |
|---|---|---|
| L1 静态 | 语法编译、顶层重复定义、`.bat` 是否纯 ASCII、前端产物是否齐全、`违禁词库.txt` 与代码内置词库是否逐行一致、`公告\` 目录与房间公告结构、资料字段的公开边界（哪些能免费广播）、房主权限清单、活动消息的分档清单与前端折叠带、控制台引用的 `manage` 能力是否都存在、清空记录只删 `messages` 表、**成员列表读的列白名单里没有 `password_hash`**、**控制台的基础礼物名字与 `app.py` 的 `STARTER_ITEMS` 一致** | 0.4 秒 |
| L2 单元 | `tests\test_*.py` 里的全部用例（新加测试文件会自动带上，不用改脚本） | 约 140 秒 |
| L3 端到端 | 自动挑一个空闲端口、在临时目录里起真实服务：HTTP 接口、按房间公告、公告更新的聊天区提示、房主授权与越权拦截、按房间禁言隔离、活动消息分档（实时与历史同档）、WebSocket 双向收发、违禁词打码、重置密码回归 | 约 6 秒 |
| L4 控制台 | 主窗口 8 个按钮的布局（「服务控制」「账号数据」两行 + 行首标签、两行不溢出窗口）、成员列表窗口的完整流程（老库缺列也能读、数据里没有密码字段、搜索与角色筛选、CSV 表头与防公式注入、选中记忆、重置密码真的写库） | 约 4 秒 |

L2 最慢，是因为里面要跑 PBKDF2 十二万轮口令哈希和真实的等待；想快速过一眼就 `--only L1`。

**跑这个检查很安全**：服务和数据库都在系统临时目录里新建，全程不碰 `data\chatroom.db`，也不占用 9000 端口，跑完自动删干净。
公告目录同样会重定向到临时目录，**不会动你正在用的 `公告\`**；收尾还有一道「污染核对」专门复核这件事。
退出码 `0` 表示全过，`1` 表示有失败（失败清单和服务日志尾部会打在最下面），`2` 表示参数或环境不对。

## 目前的边界

每发送一条正常消息获得 2 点经验和 1 点金币，每升一级额外奖励 10 点金币；等级每 50 点经验提升一级，并显示对应称号（初来乍到、活跃成员、聊天达人、房间红人、资深玩家、传奇人物等）。金币和经验分开计算，商城与互动消耗金币，等级只看经验；违规消息会被屏蔽、扣除 5 金币，也不会获得这条消息的正常聊天经验。注册用户的等级会保存，游客只在当前进入期间保留。

游客只能聊天、真心话大冒险和小游戏答题；抽奖、转盘、大喇叭、发/抢红包、竞猜、等级商城这些消耗金币的功能需要注册账号（游客没有数据库记录，金币和道具无法保存）。

商城按礼物、徽章、宠物用品三类排列；头像在“我的资料”里选择，不属于商城商品。鲜花、掌声、飞吻、礼花是 1 金币一个的基础礼物，可重复购买；玫瑰花束、钻石、生日蛋糕、冠军奖杯价格更高。聊天框上方的“送礼物”可把拥有的物品送给在线用户，“用道具”可使用自己的头像或佩戴徽章；收礼者会收到提示并获得物品。

徽章一共七枚（爱心、星星、音符、幸运、火焰、奖牌、彩虹），价格越高越稀有。兑换后会自动戴上，也可以随时在商城里点“佩戴”或在“用道具”里换着戴；同一时间只显示一枚，昵称旁的那个小图标就是当前佩戴的徽章。

“等级商城 → 我的物品”可按类型筛选、按数量或回收价排序，并按数量批量回收徽章和礼物。“选择重复物品”默认每种保留一件。回收价＝当前商城价格的一半向下取整、**最低 1 金币**（基础礼物鲜花/掌声/飞吻/礼花定价 1 金币，回收各得 1 金币）；回收后库存减少，魅力和经验不变。最后一枚正在佩戴的徽章卖出后取消指定佩戴，若还有其他徽章则按原有规则自动展示。物品不会过期。管理员仍显示无限金币，回收只减少库存。

个人资料卡支持点击图片头像查看原图；右侧在线列表点击自己可以打开免费只读资料卡，不能从这里编辑。

头像图片放在 `avatars` 文件夹，支持 png、jpg、jpeg、gif、webp、bmp。放入图片后重启服务，头像选择器会自动读取这些图片；文件夹里有图片时只显示这些自定义头像，文件夹为空时才显示内置默认头像。建议使用正方形图片，推荐 256x256 或 512x512。

自定义聊天表情放在 `emojis` 文件夹，支持 png、gif、webp、jpg、jpeg，也支持中文文件名。放入图片后刷新网页，点击聊天框上方的表情按钮即可看到；文件夹里有图片时只显示这些自定义表情，文件夹为空时才显示内置表情；英文文件名会自动变成短代码，例如 `smile.gif` 会插入 `:smile:`，中文文件名或重复的短代码会自动生成稳定标识，显示标题仍保留文件名。重置系统数据不会删除表情图片。建议使用 64x64 或 128x128 的透明图片，动图建议控制在 1MB 以内。

55 台学生机的文字聊天并发在当前单进程设计范围内。

**身份、道具、徽章三者的关系**（互相不冲突，各管一摊）：

- **身份**决定「能做什么」：管理员 > 房主（仅限本房间）> 普通用户 > 游客。身份不是花钱买的，由管理员授予或按注册方式决定。
- **道具**决定「能玩什么」：抽奖、转盘、红包、竞猜这些消耗金币的玩法，游客用不了。
- **徽章**只是「好看」：昵称旁边的小图标，跟权限一点关系都没有 —— 房主也可以不戴徽章，戴了徽章的普通用户也不会因此多出任何权限。
